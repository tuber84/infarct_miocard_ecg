Android выбран первым техническим прототипом для разработки на Windows. Выбор основной мобильной платформы автором и окончательный выбор оболочки остаются открытыми. iOS-проект не создавался.

## Как устроена сборка

`capacitor.config.json` задаёт приложение `ru.cardioatlas.ecg`, имя «КардиоАтлас ЭКГ» и каталог `dist`. Команда синхронизации копирует интерфейс, клинические данные, модель и текстуру в `android/app/src/main/assets/public/`. `server.url` отсутствует: приложение предназначено для загрузки ресурсов из APK. Ссылки на клинические рекомендации открывают внешние документы и требуют сети.

В мобильной оболочке начальный режим — «Тренировка», в браузере и Electron — «Атлас». 3D-атлас вынесен в ленивый чанк (`AtlasView`), чтобы ускорить холодный старт тренажёра. Определение платформы находится в `src/platform/runtime.ts`, вне медицинского ядра. Настройки `SystemBars` (`insetsHandling: native`, `style: LIGHT`) и светлая тема `AppTheme.NoActionBar` передают системные отступы и светлое оформление панелей Android; их также нужно проверить на телефоне в портретной и альбомной ориентациях.

Навигация между режимами и мобильными вкладками этапа синхронизирована с `window.history`, а `MainActivity.java` перехватывает системную кнопку/жест «Назад» через `OnBackPressedCallback` (вызывает `webView.goBack()` при наличии шага назад). Двухпальцевый pinch-to-zoom на ленте ЭКГ во время жеста масштабирует сцену через CSS `transform` и перерисовывает `<canvas>` один раз на `touchend` с ограничением `dpr ≤ 2` для защиты от перерасхода видеопамяти на экранах высокой плотности.

Попытки сохраняются существующим адаптером localStorage в данных WebView приложения. Запись происходит при ответе и переходе этапа. Данные не переносятся из браузера или Electron; очистка данных приложения удаляет попытки. Гарантии переноса при обновлении и резервное копирование пока не проверены.

## Подготовка Windows

Требования Capacitor 8: Node.js 22+, Android Studio 2025.2.1 или новее и Android SDK. Java поставляется с Android Studio; проект использует JDK 21. Установите SDK Platform **36**, Platform Tools и Build Tools, необходимые Gradle. Минимальный API приложения — 24; это порог установки, а не подтверждение проверки на всех поддерживаемых версиях Android.

Официальные инструкции: [окружение Capacitor](https://capacitorjs.com/docs/getting-started/environment-setup), [Android](https://capacitorjs.com/docs/android), [рабочий процесс](https://capacitorjs.com/docs/basics/workflow).

Путь SDK обычно `%LOCALAPPDATA%\Android\Sdk`; можно задать `ANDROID_HOME` или указать `sdk.dir` в `android/local.properties`. Команда сборки ищет Java в `JAVA_HOME`, затем в локальном каталоге проекта `.tools/jdk21`, затем в стандартном каталоге `C:\Program Files\Android\Android Studio\jbr`, затем в PATH. Нестандартный каталог задайте через `JAVA_HOME`. Если Android Studio поставляется с Java 25, используйте JDK 21: Gradle 8.14.3 этого проекта не запускается на Java 25. Для сборки через Android Studio выберите тот же JDK в настройке **Build Tools → Gradle → Gradle JDK**.

Android-команды используют `scripts/android.cjs`: TypeScript, Vite и Capacitor запускаются текущим Node.js по явным путям. Вложенных вызовов `npm` нет, поэтому отсутствие `npm.cmd` в PATH дочернего `cmd.exe` не ломает сборку. Если сама команда `node` недоступна в терминале, можно вызвать этот файл полным путём к установленному `node.exe`.

## Команды

```powershell
# Собрать веб, скопировать в Android и проверить комплектность без SDK
npm run android:sync

# Открыть подготовленный проект в Android Studio
npm run android:open

# Собрать отладочный APK (нужны Java и SDK)
npm run android:apk

# Установить на подключённый телефон с включённой отладкой USB
adb install -r android/app/build/outputs/apk/debug/app-debug.apk
```

Первая нативная сборка скачивает Gradle и зависимости и требует интернета. Полученный debug APK предназначен для локальных испытаний. Релизная подпись и публикация не настроены. После правок интерфейса повторите `android:sync` или `android:apk`; скопированный каталог `assets/public` вручную не редактируют. APK можно скопировать на телефон и открыть через файловый менеджер: установка поверх предыдущей сборки с той же подписью должна сохранить данные приложения; отдельно проверьте сохранение попытки. Удаление приложения или очистка его данных может удалить локальный прогресс.

`npm run check:android` сравнивает SHA-256 всех ресурсов `dist` с Android-копиями, проверяет модель, текстуру, подключение Capacitor и отсутствие удалённого dev-сервера. Эта проверка подтверждает комплектность; она не проверяет работу WebView или APK.

## Проверка на устройстве

1. Установить APK, включить авиарежим и запустить приложение заново. Открыть тренировку и пройти все этапы, затем открыть анатомию.
2. Проверить чтение ЭКГ, прокрутку и переход к группам отведений. Развести и свести два пальца на ленте при выключенном и включённом калипере: масштаб должен меняться в пределах 75–160%, а область под пальцами оставаться видимой. Проверить калипер при 25/50 мм/с и 5/10 мм/мВ: завершённое измерение сохраняется при масштабировании, при смене скорости или усиления рамка сбрасывается. При включённом калипере один палец рисует рамку; для прокрутки выключите калипер.
3. После ответа свернуть приложение и вернуться; затем принудительно закрыть и открыть. Проверить восстановление этапа и сохранённого ответа.
4. Проверить поворот экрана, системную кнопку/жест «Назад», видимость верхних вкладок и нижних кнопок рядом с системными панелями.
5. Проверить модель сердца, переключение анатомии/КАГ, локальное хранение и внешние ссылки. Зафиксировать модель телефона, версию Android/WebView, время запуска и замечания.

Этап мобильного прототипа считается завершённым после этой проверки и исправления выявленных проблем. Эмуляция касания в Chromium остаётся регрессионной проверкой интерфейса.
