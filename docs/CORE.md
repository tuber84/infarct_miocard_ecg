# Независимое ядро и сценарии

Реализация первого архитектурного этапа от 22.11.2026. Общая стратегия — [ARCHITECTURE_ROADMAP.md](ARCHITECTURE_ROADMAP.md).

## Структура

| Путь | Ответственность |
| --- | --- |
| `src/core/index.ts` | Публичные экспорты ядра |
| `src/core/types.ts` | Типы отведений, профилей, стадий, локализации |
| `src/core/ecg/ecgEngine.ts` | Генерация сигнала, реперы и измерения |
| `src/core/ecg/localizer.ts` | Сопоставление ручной разметки с примерами |
| `src/core/content/coronaryCases.ts` | 22 медицинских профиля (ИМпST, ИМбпST, блокады и мимики) и коррекция по типу кровоснабжения |
| `src/core/content/clinicalGuidelines.ts` | Ссылки, критерии и пояснения российских КР |
| `src/core/scenarios/types.ts` | Контракты примера атласа и клинической задачи |
| `src/core/scenarios/catalog.ts` | Каталог существующих примеров и реестр источников |
| `src/core/scenarios/validate.ts` | Проверка связности авторских данных |
| `src/core/scenarios/firstCase.ts` | Первый авторский клинический случай |
| `src/core/scenarios/training.ts` | Создание попытки, фиксация ответа, переходы и представление текущего этапа |
| `src/platform/trainingStorage.ts` | Локальное хранение попыток в браузере/Electron |
| `src/components/TrainingPanel.tsx` | Экран прохождения случая и разбора |
| `src/presentation/heartLandmarks.ts` | Координаты и замена маркеров конкретной 3D-модели; вне ядра |

Внутри ядра допустимы только импорты других файлов ядра. В нём нет доступа к DOM, React, Three.js, Electron, сети или хранилищу. Русские учебные тексты и обозначения допускаются: отсутствие платформенных зависимостей не требует удаления медицинских пояснений.

`src/ecg/*`, `src/data/coronaryCases.ts`, `src/data/clinicalGuidelines.ts` и `src/types/ecg.ts` оставлены для совместимости старых импортов. Они не содержат второй реализации. Новые потребители используют `src/core/`.

## Использование

Пример TypeScript-кода для любой оболочки или теста:

```ts
import {
  getAtlasScenario,
  validateScenario,
  resolveCaseForDominance,
  computeStageModifiers,
  generateLeadSignal,
} from './src/core'; // Путь относительно потребителя.

const scenario = getAtlasScenario('rca_prox');
const errors = validateScenario(scenario);
if (errors.length) throw new Error(errors.join('\n'));

const resolved = resolveCaseForDominance(scenario.profileId, 'right');
const signalMv = generateLeadSignal(
  'II', resolved.leads.II, computeStageModifiers(0.35, false),
  5, 1000, resolved.caseData.defaultHeartRate,
  { artifacts: false, aivr: false },
);
// Float32Array в мВ; экран, масштаб бумаги и ввод выбирает оболочка.
```

`index.ts` — удобная общая точка входа. Прямые импорты из подмодулей допустимы, например если отображению ЭКГ нужен только генератор. Это исходные TypeScript-модули; публикация отдельного npm-пакета и готовая сборка для Node.js пока не предусмотрены. Тесты выполняют транспиляцию установленным TypeScript.

## Два вида сценариев

`AtlasScenario` с `kind: 'atlas'` ссылается на один из существующих профилей через `profileId`. Идентификатор сценария имеет вид `atlas:rca_prox`; идентификатор профиля — `rca_prox`. У сценария есть версия схемы, редакция содержания, цели, допущения и ссылки на источники. Текущий статус `partially-reviewed` отражает проведённый аудит и оставшиеся ограничения.

`ClinicalCaseScenario` с `kind: 'clinical-case'` задаёт пациента, упорядоченные этапы `steps`, вопросы и итоговый разбор. Этап может содержать информацию, синтетическую ЭКГ либо результат тропонина/ЭхоКГ/КАГ. Результаты исследований пока представлены текстом; численные единицы и референсные пределы нужно явно указывать в авторском содержании.

Вопрос предусматривает один выбор и список допустимых вариантов `acceptedChoiceIds`: так можно принять несколько обоснованных альтернатив. Механика предъявления вопроса, фиксации ответа и оценки реализована в `training.ts`. `getTrainingView()` выдаёт текущий этап и варианты без правильных ответов; обратная связь доступна после фиксации, итоговый разбор — после последнего этапа. Полный авторский объект содержит ответы; это учебное управление раскрытием данных, не защита экзамена от изучения исходного кода.

Существующие примеры атласа не получили выдуманных анамнеза, возраста, лабораторных результатов или вопросов. В ядре находятся два синтетических клинических случая. «Дежурство №1 · Боль в груди» содержит три вопроса и пять этапов. «Дежурство №2 · Первая ЭКГ» содержит четыре вопроса и связывает отметки на ЭКГ с выбором проекции, контрастированием и точкой поражения на С-дуге. Медицинские основания и границы проверки описаны в [TRAINING.md](TRAINING.md).

## Источники и версии

`GUIDELINE_SOURCES` содержит редакцию, год публикации и ссылку на документ. `SourceReference` указывает идентификатор документа, разделы и область подтверждения. Ссылка на рекомендации не подтверждает автоматически геометрию 3D, каждую числовую амплитуду или все утверждения профиля.

`schemaVersion` меняется при несовместимом изменении структуры; `revision` — при изменении содержания конкретного сценария. Попытки сохраняют обе версии вместе с идентификатором сценария. Автоматическая миграция между несовместимыми редакциями пока не реализована: такие записи не восстанавливаются и не перезаписываются.

`validateScenario()` предназначена для типизированных авторских объектов. Она выявляет отсутствующие профили/источники, повторные идентификаторы, ошибки связей ответов и основные нарушения структуры. Она не выполняет клиническую экспертизу и не заменяет полноценный разбор неизвестного JSON при будущем импорте файлов.

## Проверки

```powershell
npm run test:core
npm run test:ecg
npm run test:clinical
npm run test:training
npm run build
```

`test:core` сначала компилирует ядро через `tsconfig.core.json` с `lib: ["ES2020"]` и `types: []`, затем проверяет граф импортов, каталог и контракт клинической задачи в Node.js. Проверки генератора и локализатора напрямую импортируют реализацию ядра.

При выделении ядра данные всех 16 профилей и 15 привязок к 3D были сравнены с исходными. Хеш отсчётов сигналов совпал для всех профилей, 17 отведений, обоих типов кровоснабжения, шести стадий и двух историй реперфузии при исходной ЧСС сценария. Это проверка сохранения поведения при переносе, а не новая медицинская валидация.
